# LiaoYu 咨询陪伴服务平台 设计文档

- 日期：2026-10-24
- 状态：已确认（内测版 MVP）

## 1. 产品定位

微信小程序形态的**咨询陪伴类**双边服务平台（心理、情感、职业规划、健身/饮食指导等）。

- 老师入驻并提供服务套餐，用户选择老师付费，老师对其用户长期负责。
- 老师临时有事时，可指定代班老师，用户确认后由代班老师临时服务，服务关系仍属原老师。
- 平台总负责人管理所有老师（审核、定级、结算、纠纷）。
- 老师有等级（信任标签），用于展示，价格由老师自定。

核心差异点：**服务关系可追踪、可代班、按服务进度结算**。

## 2. 角色与端

| 角色 | 使用端 | 核心诉求 |
|---|---|---|
| 用户 | 微信小程序 | 找到靠谱老师，服务不断档 |
| 老师 | 同一小程序（认证后切换"老师工作台"） | 获客、稳定收入、可请假 |
| 平台负责人 | 独立的电脑管理网页 | 控质量、管老师、管结算 |

不做面向用户/老师的网页版。

## 3. 已确认的关键决策

| 维度 | 决策 |
|---|---|
| 服务类型 | 咨询陪伴类 |
| 交付方式 | 日常 IM 消息陪伴 + 定期预约语音/视频通话 |
| 套餐 | 单次 / 包月 / 包季 / 包年；年包仅 L3 及以上老师可开放 |
| 代班 | 老师请假时指定 1~3 位同级或更高级代班老师（需对方同意），用户从中选；代班期间的日计提全部归代班老师（与 6.1 分段计提一致）；关系仍属原老师 |
| 等级 | 仅展示/信任标签，价格老师自由定；入驻人工初评（最高 L3），系统月度生成升降级建议，负责人审核确认 |
| 内测收款 | 复用 divination 项目的 ZPAY（支付宝）收银台 + 异步回调自动确认 |
| 正式上线收款 | 微信支付（小程序内支付） |
| 老师结算 | 系统计提账本 + 负责人线下人工打款并在后台登记 |
| 退款/换师/投诉 | MVP 全部人工工单处理 |
| 管理功能 | 独立电脑管理网页，独立管理员账号 |
| 数据库 | 独立数据库，与 divination 完全隔离 |

## 4. 整体架构

```
微信小程序（用户 / 老师 双身份）──┐
                                  ├──► 后端服务（Node.js + Express）──► 独立数据库
负责人管理网页（电脑浏览器）──────┘           │
                                              ├── ZPAY 支付宝（内测收款，回调自动确认）
                                              ├── 腾讯云 IM（消息）
                                              └── 腾讯云 TRTC（预约通话）
```

| 层 | 选型 | 说明 |
|---|---|---|
| 小程序 | 原生小程序 + TypeScript | 用户/老师双身份切换 |
| 管理网页 | Vue3 + Element Plus | 由后端静态托管于 `/admin`，独立账号登录 |
| 后端 | Node.js + Express + JWT | 对齐 divination 技术路线，便于复用支付代码 |
| 数据库 | 内测 SQLite（独立文件），数据访问层封装 | 上线可迁 MySQL |
| 消息 | 腾讯云 IM | 消息回调进后端：内容安全、危机关键词、回复时效统计 |
| 通话 | 腾讯云 TRTC | 通话开始/结束回调，作为计次与准时率依据 |
| 收款 | `PaymentProvider` 接口 | 实现：`ZPayProvider`（内测）、`WechatPayProvider`（上线） |
| 打款 | `PayoutProvider` 接口 | 实现：`ManualPayoutProvider`（人工打款登记） |

## 5. 功能清单

### 5.1 用户端（小程序）
- 微信登录（code2Session 换 openid）。
- 首页：按方向、等级、价格、评分筛选老师。
- 老师详情：简介、资质（脱敏）、等级徽章、评价、套餐列表。
- 下单付款（内测流程见第 7 节）。
- 我的服务：IM 聊天、预约通话（在老师可约时段内选择，消耗套餐次数）。
- 代班确认：收到请假通知后，从候选老师中选择，或选择"等原老师回来"（暂停顺延）。
- 售后：评价、投诉、申请退款/换师（生成人工工单）。

### 5.2 老师端（小程序 · 老师工作台）
- 入驻申请：实名、资质证书、擅长方向 → 等待审核定级。
- 套餐管理：类型、价格、包含通话次数、承诺回复时效（如 12 小时内）。
- 学员管理：服务中学员、到期提醒、服务记录。
- 排班：设置可预约时段。
- 请假：选择时段 → 指定 1~3 位同级或更高级代班老师 → 对方同意 → 通知受影响学员。
- 代班邀请：接受/拒绝其他老师的代班邀请。
- 收入：待结算、已打款、代班收入明细。

### 5.3 负责人管理网页
- 管理员账号登录（独立账号，密码加密存储，操作留审计日志）。
- 老师审核与初始定级；月度升降级建议的审核确认。
- 订单查询：按用户 / 老师 / 时间筛选，可导出（"哪个用户给哪个老师付了多少"）。
- 结算：每周生成"老师应得金额"清单 → 线下打款 → 标记已打款并上传凭证。
- 工单：退款、换师、投诉的人工处理。
- 危机事件、私下交易风险提示的处理记录。
- 配置：平台抽成比例（可按等级区分）、结算周期。
- 数据看板：GMV、活跃老师、续费率、投诉率。

## 6. 核心数据模型

| 表 | 说明 |
|---|---|
| `users` | 用户（openid、昵称、角色标记） |
| `teacher_profiles` | 老师资料、资质、当前等级、状态（审核中/正常/停用） |
| `packages` | 老师套餐（类型、价格、有效天数、通话次数、回复时效、是否上架） |
| `orders` | 订单：`user_id`、`teacher_id`、`package_id`、`amount`、`out_trade_no`、`trade_no`、`pay_provider`、`status`、`paid_at` |
| `service_relations` | 服务关系：用户×原老师×套餐、起止日期、剩余通话次数、状态；下单时快照套餐金额/天数/通话次数/回复时效（`reply_hours`），老师改套餐不影响进行中的关系 |
| `service_segments` | 服务分段：`relation_id`、负责老师、起止日期、类型（normal / substitute / paused） |
| `leaves` | 请假记录 |
| `substitute_candidates` | 代班候选（请假 × 老师 × 是否同意） |
| `appointments` | 通话预约（时段、实际开始/结束、归属老师、状态） |
| `accruals` | 日计提明细，`(relation_id, date)` 唯一 |
| `settlements` | 周结算批次（老师 × 周期 × 应得金额 × 状态） |
| `payouts` | 打款记录（结算 × 金额 × 凭证 × 操作人） |
| `tickets` | 工单（退款/换师/投诉，人工处理）；含 `clawback_cents`（应追回金额，仅记录） |
| `reviews` | 评价 |
| `level_suggestions` / `level_history` | 等级建议与变更历史 |
| `crisis_events` | 危机关键词事件 |
| `admins` / `audit_logs` | 管理员账号与审计日志 |

### 6.1 关键设计：服务分段

服务关系的有效期被拆为若干连续分段：

- **正常**：负责老师 = 原老师。
- **代班**：插入一段负责老师 = 代班老师的分段。
- **暂停**：插入一段暂停分段，服务关系结束日期顺延相同天数。

日计提只需查看当天落在哪个分段：正常/代班分段计入对应负责老师，暂停分段不计提。代班与暂停复用同一套逻辑，不写特殊分支。

### 6.2 服务关系状态机

```
待支付 → 服务中 ⇄ 代班中 → 已到期 / 已退款(人工) / 已换师(人工)
            ⇅
          暂停（有效期顺延）
```

### 6.3 续费

同一用户对同一老师已有未到期的周期服务时，新购周期服务从原服务结束日次日开始（顺接），不与现有服务重叠。

## 7. 资金流程

### 7.1 内测收款（ZPAY 支付宝）

微信小程序内无法打开支付宝收银台，内测采用"复制链接到浏览器付款"：

1. 用户在小程序选老师 + 套餐，点击下单。
2. 后端创建订单（记录用户、老师、套餐、金额、订单号），生成 ZPAY 支付链接。
3. 小程序展示"复制支付链接 → 在手机浏览器打开 → 支付宝付款"。
4. ZPAY 异步回调 `/api/pay/notify`：验签 → 校验金额 → 订单置为已付款 → 建立服务关系（幂等）。
5. 小程序轮询订单状态，开通成功后跳转"我的服务"。

内测仅使用小程序**体验版**（成员白名单），不提交审核。

### 7.2 正式上线收款

新增 `WechatPayProvider`，小程序内直接调起微信支付，第 2、4 步逻辑不变。

### 7.3 计提与结算

| 套餐类型 | 计提时机 |
|---|---|
| 单次 | 通话完成，且用户确认或 48 小时内无异议 |
| 月 / 季 / 年 | 按天计提：日额 = 套餐价 ÷ 有效天数，归当天分段的负责老师 |
| 暂停分段 | 不计提 |
| 有处理中工单 | 冻结该服务关系的计提 |

- 老师应得 = 计提金额 × (1 − 平台抽成比例)。
- 每周生成结算清单，负责人线下打款后在管理网页登记凭证。

## 8. 等级评定

- 等级 L1~L5（展示名可包装）。
- 入驻初评：负责人依据资质、从业年限、试聊考核定级，最高 L3。
- 月度指标：累计服务人·天、近 90 天平均评分、续费率、回复时效达成率、通话准时率、有效投诉数。
- 每月 1 日生成升降级建议，负责人确认后生效；有效投诉成立为红线，直接进入降级/下架审核。
- 代班资格：同级或更高级，以请假当日等级为准。

## 9. 异常处理

- 支付回调、计提任务均幂等；订单号唯一索引。
- 回调金额与订单不符：不开通，记异常并告警。
- 请假后候选老师无人同意或用户 48 小时内未选择：自动转为暂停顺延。
- 请假已开始但用户尚未选择：未选择期间先按暂停分段处理（不计提、有效期顺延）；用户选定代班老师后，自选定当日起改为代班分段；超 48 小时未选则保持暂停。
- 请假期间已有的通话预约：请假生效时自动取消，退还通话次数，并通知用户重新选择（改约代班老师或等原老师回来）。
- 代班冲突：发邀请时排除请假时段与自身请假重叠的老师；已同意代班的老师不得提交与代班时段重叠的请假，须先由原老师撤销代班。不设代班人数上限。
- 老师降级至 L3 以下：自动下架其在售年包；已售年包照常服务至到期。
- 预约通话老师超时 15 分钟未上线：记老师爽约，不扣用户次数，计入准时率。
- 工单处理期间冻结计提与结算；结案后按结果重算或退款（人工）。
- 退款工单结案：停止该服务关系后续计提，在工单上记录应追回金额（`clawback_cents`）；是否追回、如何追回由负责人线下处理，系统不自动扣减老师结算。

## 10. 合规与风控

- 内测仅用体验版。**正式上线前必须确认**：小程序类目资质（心理/情感等）、实时音视频类目、微信支付商户号。
- 文案避免"诊断""治疗"等医疗用语。
- 敏感个人信息：隐私协议单独同意、加密存储、聊天记录留存期限、后台调阅需留审计日志。
- IM 内容接入微信内容安全检测。
- 防私下交易：手机号/微信号等关键词提示并记录。
- 危机干预：自伤类关键词触发热线提示，并通知老师与负责人，记录处理过程。

## 11. 测试策略

- 单元测试：服务关系状态机、分段计提（正常/代班/暂停/跨月）、等级建议计算、结算金额。
- 集成测试：ZPAY MOCK 模式下单与回调；`ManualPayoutProvider` 结算流程。
- 端到端：购买 → 聊天 → 预约通话 → 请假代班 → 周结算 全链路。

## 12. 范围

**MVP（P0）**：微信登录、老师入驻审核定级、套餐、下单付款（ZPAY）、IM、预约通话、请假代班、日计提与周结算登记、评价、人工工单、月度等级建议、内容安全与危机提示、管理网页基础看板与订单导出。

**二期**：微信支付、自动退款与换师折算、优惠券与营销、分销、老师内容动态、自动打款（灵活用工/转账到零钱）。
